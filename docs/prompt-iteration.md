# AI 评分员 Prompt 迭代记录

> 作品集文档 · 2026-08-06
> 项目：大模型译文审校可靠性评测
>  本文档记录 AI 评分 Prompt 从 v0 到 v2 的三轮迭代：每个 badcase 的完整样本、归因逻辑、修复动作与验证结果，全部基于真实运行数据。

---

## 一、30s 看懂这个文档

### 背景

评测项目需要回答一个问题：++**AI 能否替代人工做翻译质量审校++？** 

方法：让 AI 按我们定义的四维评分框架（Terminology / Accuracy / Locale / Audience）对 45 份译文打分，再与人工参考标注（专业人工评分，下称 ground truth）逐条对照，计算人机一致性。

AI 的评分标准很大程度上依赖 **Prompt（评分规则说明书）**。本文档记录这四份 Prompt 的迭代过程。

### 核心数据（8 条联调样本）


| 版本          | 人机一致（MATCH） | 分歧（DIFF） | 一致率       | 累计修复规则  |
| ----------- | ----------- | -------- | --------- | ------- |
| v0 基线       | 4           | 4        | 50%       | 0 条     |
| v1          | 5           | 3        | 62.5%     | 2 条     |
| v2          | 6           | 2        | 75%       | 4 条     |
| **Qwen 校准** | **7**       | **1**    | **87.5%** | 4 条（继承） |


**口径说明：50% → 62.5% → 75% 是 DeepSeek 联调阶段随 Prompt 迭代的一致率变化；切换正式评分模型为 Qwen 后，同一 8 条校准样本一致率为 87.5%（且无 INCONSISTENT 输出矛盾）。Prompt 迭代与模型校准是两层动作，跨模型数值不构成同一条优化曲线。**

### 一句话结论

> Prompt 迭代的本质是 **badcase 归因闭环**：发现 AI 判错 → 诊断错因（规则缺失 / 规则表述不清 / 模型能力边界）→ 针对性修复 → 复验。三轮迭代修复了 6 个 badcase 中的 4 个，剩余 2 个诊断出深层原因，为正式全量评分（180 次）提供了修正后的评分标准。

## 二、方法论：怎么判断 badcase 的错因



### 2.1 什么是 badcase

**Badcase = AI 输出与人工参考标注（ground truth）不一致的样本。** 它是 Prompt 迭代的最小改进单位。

本项目中，badcase 的定义精确为：同一条译文，人工判定的 severity 与 AI 输出的 severity 不一致（DIFF）。

### 2.2 归因三问法（判断错因的决策树）

不是"一个一个试"，而是按顺序回答三个问题，逐层定位：

```
Q1：评分规则里写了吗？
    ├─ 没写 → 结论：规则缺失（Prompt 缺陷）
    └─ 写了 → 进入 Q2

Q2：补上明确规则后，AI 判对了吗？
    ├─ 判对了 → 结论：规则表述不清（Prompt 缺陷）
    └─ 还判错 → 进入 Q3

Q3：规则明确 + 示例都给全，AI 还是错？
    └─ 结论：模型能力边界（修 Prompt 无收益）
```

**原则：先怀疑自己（Prompt），再怀疑模型（能力）。** 因为 Prompt 是可控的，模型能力是不可控的——把可控的修好，剩下的才轮到不可控的。

### 2.3 什么是人工参考标注（ground truth），它可靠吗

**本文的 ground truth = 人工参考标注 = 本项目的专业人工评分。**

它可靠性的保障有三个：

1. **专业背景**：评分者为翻译学硕士，专业对口
2. **流程约束**：评分走三问分流流程 + 维度锚点，而非想当然
3. **对抗性审查**：评分经过三轮对抗性审查（F1-F9 审查、K3 交叉核查、千问核查），每一处定级都有 notes 论证可追溯

**诚实边界**：ground truth 不是"绝对真理"，是"当前方法下最可信的基准"。 每条评分后notes 独立自含、附出处，每条判定可复核，具有可审计性。

### 2.4 怎么判断迭代方向是对的


| 指标           | 含义            | 本项目表现                  |
| ------------ | ------------- | ---------------------- |
| badcase 修复率  | 上一轮的分歧这轮消失了几条 | v1 修复 1 条，v2 修复 3 条    |
| 新增 badcase 率 | 修旧的是否引发新分歧    | 三轮无新增（0 条）             |
| 人机一致率趋势      | 整体一致性是否上升     | 50% → 62.5% → 75%，单调上升 |

## 四、v1 迭代：修复 2 个系统性 badcase



### 4.1 Badcase 样本与归因



#### Badcase 1：Locale 维度——AI 拿原文格式评译文（S003/S007）

**样本（S003）**：

- 原文：`$5 first month, then $20/mo.`（nudge 产品定价）
- 译文（B 工具）：`首月仅需 5 美元，之后每月 20 美元。`
- 人工判定：**Neutral**（"5美元/20美元为数字+货币名称，标准中文货币格式"）
- AI 判定：**Minor**（AI notes："原文使用英文货币符号 $5、$20/mo"）

**归因（Q1 命中）**：评分规则里从未说明"评分对象是译文，原文格式只作参照"。AI 看到原文的 $ 符号，误以为是译文的格式问题——**规则缺失**。

**修复**：Locale Prompt 常见误判提醒新增第 7 条：

> 评分对象是译文，不是原文。原文使用英文格式（如 $5、$20/mo）是正常的，只要译文已本地化为中文格式（如"5 美元"）就不构成偏离；仅当译文本身使用非中文格式才扣分。



#### Badcase 2：Audience 维度——AI 缺中文营销常识（S004/S008）

**样本（S004）**：

- 原文：`Don't create. Type plain text...`（nudge 营销文案）
- 译文（B 工具）：`拒绝繁琐输入：只需输入纯文本...`
- 人工判定：**Neutral**（"拒绝X句式是典型的中国互联网营销文案话术，节奏感和冲击力强，契合年轻/效率工具受众"）
- AI 判定：**Minor**（AI notes："原文 Don't 为使役句，译文统一改为拒绝X结构……"）

**归因（Q1 命中）**：评分规则未包含中文营销领域知识。"拒绝X""一键X""仅需XX元"是中文互联网高频地道表达，AI 没有这个常识，凭"翻译腔"的观感判了 Minor——**规则缺失（领域知识未注入）**。

**修复**：Audience Prompt 常见误判提醒新增第 6 条：

> 中文营销高频句式是地道表达，不构成语域偏离。"一键X""拒绝X""仅需XX元""不用/不要/不会"均为中文互联网营销与产品文案的高频地道表达，受众完全适应，判 Neutral。仅在渲染过度时才触发第三问评估。



### 4.2 v1 复验结果


| 结果               | score_id | 说明                  |
| ---------------- | -------- | ------------------- |
| **B3（S004）修复**   | MATCH    | ✅ 规则生效，AI 判 Neutral |
| B1/B2（S003/S007） | 仍 DIFF   | ❌ 修复未生效             |
| **B4（S008）**     | 仍 DIFF   | ❌ 同维度但未修复——提示错因不同   |


**v1 复验揭示的关键信息**：同模式的 B3 修好了，B4 却没修好 → 说明 B4 的错因与 B3 **不是同一个**——"逐条归因"比"按模式归因"更精细。

## 五、v2 迭代：第二层归因，修复 3 个 badcase



### 5.1 第二层归因：读 AI 的实际 notes 定位真错因



#### Badcase 3：S008——错因不是句式，是"自律类短语"

**样本（S008）**：

- 原文：`Don't let yourself off. Lock $5 on a deadline.`
- 译文（C 工具）：`不要轻易放过自己。为截止日期锁定 5 美元。`
- 人工判定：**Neutral**（"轻易是中国自律类文案惯用措辞，避免绝对化带来的压迫感，符合中文受众对社会性劝说的接受习惯"）
- AI 判定：**Minor**（AI notes："主要偏差在于'不要轻易放过自己'一句……对应英文 Don't let yourself off……语域略显僵硬"）

**归因**：AI 承认"高频句式接受度高"，但卡在"轻易放过自己"——它不知道这是中文自律/激励类文案的惯用表达。**规则只覆盖了句式（拒绝X），没覆盖短语（轻易放过自己）**。

**修复**：Audience Prompt 新增第 7 条：

> 中文自律/激励类文案的惯用短语是地道表达。"不要轻易放过自己""别让自己松懈"等为中文自律/激励类文案的惯用表达，与原文 Don't let yourself off 的语义和语域匹配，不构成语域偏离或僵硬翻译。



#### Badcase 4：S007——notes 与 severity 输出矛盾

**样本（S007）**：

- 译文（C 工具）：`不用创建任务……首月 5 美元，之后每月 20 美元。`
- 人工判定：**Neutral**
- AI 判定：**Minor**，但 **AI notes 写的是"未发现格式偏离……结论：Neutral"**

**归因**：AI 的 notes 逻辑已经判对（格式已本地化），但 severity 字段仍输出 Minor——**notes 与 severity 字段矛盾**，属于输出结构化一致性问题。

**修复**：Locale Prompt 新增第 8 条：

> notes 结论与 severity 必须一致。若 notes 判定"未发现格式偏离"或"格式已本地化"，severity 必须为 Neutral；若 notes 判定存在偏离，severity 不得为 Neutral。输出前自查一致性。



### 5.2 v2 复验结果


| 结果       | score_id    | 说明                                                         |
| -------- | ----------- | ---------------------------------------------------------- |
| B4（S008） | **MATCH** ✅ | 自律类短语规则生效                                                  |
| S007     | **部分修复** ⚠️ | notes 已写对（"未发现格式偏离，结论 Neutral"），**但 severity 字段仍输出 Minor** |
| S003     | 仍 DIFF ❌    | 见下方第三层归因                                                   |


**v2 复验的重要发现**：第 8 条规则让 AI 的 **notes 逻辑层**修正了（notes 写 Neutral），但 **severity 字段层**未跟随。这暴露了输出一致性问题比预想的更顽固，即规则在"推理层"生效，在"字段填写层"未生效。

## 六、第三层归因：S003 与 S007 的最终诊断



### 6.1 S007：输出字段一致性——规则未完全生效

- 现状：notes 写"未发现格式偏离……结论：Neutral"，severity 字段仍输出 Minor
- 诊断：模型在"叙述结论"和"填写 JSON 字段"两个环节行为不一致。第 8 条规则约束了叙述，未约束字段
- 处置：**保留规则，正式评分后统计该模式出现频率**。若频率高，v3 需在输出格式层加强约束（如要求模型先给 notes 结论、再据结论反填 severity，或输出后脚本校验字段一致性并自动纠正）



### 6.2 S003：维度错位 + 模型误读译文——能力边界

**样本（S003，v2 复验）**：

- 译文：`首月仅需 5 美元，之后每月 20 美元。`
- AI notes（v2）："货币格式已本地化为数字+货币单位……未使用英文货币符号……偏差说明：原文 $20/mo 译为 20 美元，未直接体现'每月'语义，存在微小信息省略……结论：Minor"

**归因**：

1. **模型误读译文**：译文"之后每月 20 美元"**中清楚给出"每月"**，AI 却称"未直接体现'每月'语义"。这是模型对译文文本的阅读理解错误
2. **维度错位**：即使真的漏了"每月"，那属于 Accuracy 维度（命题信息省略），不是 Locale 维度（格式问题），即AI 把命题问题归入了格式维度

**按归因三问法**：

- Q1（规则写了吗）：写了（第 7 条"评分对象是译文"）
- Q2（规则清楚吗）：清楚
- Q3（还错吗）：还错，且错在**误读译文文本本身**

**结论：模型能力边界**（对具体文本的阅读理解失误），修 Prompt 无收益。处置：接受为已知边界，正式评分后人工核验该条。

## 七、迭代总结



### 7.1 数据总览


| 版本   | 一致率        | 修复 badcase       | 新增 badcase | 归因层级                |
| ---- | ---------- | ---------------- | ---------- | ------------------- |
| v0   | 4/8（50%）   | —                | —          | 基线                  |
| v1   | 5/8（62.5%） | B3               | 0          | Prompt 规则缺失         |
| v2   | 6/8（75%）   | B4、S007（notes 层） | 0          | Prompt 规则缺失 + 输出一致性 |
| v2 终 | 6/8（75%）   | —                | 0          | S003 判定为模型能力边界      |




### 7.2 迭代闭环的四个教训（产品语言）

1. **同模式 ≠ 同错因**：B3 修好 B4 没修好，证明"按表象归类"会漏掉真实错因——逐条归因
2. **notes 说对 ≠ 字段填对**：AI 的推理层和输出层可能不一致，校验必须看最终字段而非叙述
3. **修不动也是结论**：S003 诊断为模型误读译文（能力边界），不浪费迭代轮次——知道"什么不该修"同样是能力
4. **参考基准可审计才有价值**：人工参考标注（ground truth）有 notes 支撑，badcase 归因才有依据；没有可追溯的基准，迭代就是瞎猜



### 7.3 对正式全量评分（180 条）的意义

- 四套 Prompt 已带 v1/v2 的 4 条修复规则，直接用于正式评分
- 已知边界（S003 类误读）在正式评分后人工核验
- 正式评分产出的分歧清单 = 下一轮迭代（v3）的输入

## 九、Qwen 正式评分模型校准（新增）



### 9.1 为什么换模型

联调阶段使用 DeepSeek（deepseek-chat）验证管道与 Prompt。正式评分改用 **Qwen（qwen3.8-max）**，理由：

1. 评分员必须单一（统计纯净性）
2. Qwen 是简历中既有叙事模型（文献筛选项目同款）
3. 校准实测：Qwen 无 INCONSISTENT 输出矛盾（DeepSeek 有 2 条）



### 9.2 关键工程发现：关闭思维链


| 配置                       | 单条耗时      | total_tokens | 180 条预计                 |
| ------------------------ | --------- | ------------ | ----------------------- |
| 默认（思维链开）                 | 102 秒     | 6138         | 5 小时 / 110 万 tokens     |
| `enable_thinking: false` | **4-5 秒** | **1977**     | **15 分钟 / 35 万 tokens** |


**结论**：评分任务是"读文本 + 对照规则"，不需要推理模型深度思考。关闭思维链后耗时降 95%、token 降 68%，**工具选型与参数调优本身就是成本决策**（Unit Economics 思维）。

### 9.3 Qwen 校准结果（8 条）


| 指标            | 结果                                               |
| ------------- | ------------------------------------------------ |
| 一致率           | **7/8（87.5%）**，优于 DeepSeek 的 6/8                 |
| INCONSISTENT  | **0 条**（DeepSeek 有 2 条）                          |
| 继承的 Prompt 修复 | 全部生效（S003/S004/S007/S008 均 MATCH）                |
| 新 badcase     | S006（Accuracy）：AI 将"轻易"语域问题误判进 Accuracy 维度（维度错位） |




### 9.4 S006 badcase 归因

- 人工判定：Neutral（"命题完整，不要轻易放过自己中的轻易为中文习语表达，不改变锁定押金=自我约束的命题"）
- AI 判定：Minor（notes 先写"命题完整、无遗漏无扭曲"，最后将 Don't let yourself off 的语域讨论归入 Accuracy 维度）
- 归因：**维度错位**——AI 把 Audience 维度的语域问题（"轻易"是否地道）误判进 Accuracy 维度。与 DeepSeek 的 S003（把 Locale 问题误判为 Accuracy）同类，但发生在不同维度边界
- 处置：记录为已知 badcase，全量评分后统计该模式出现频率；若高频，v3 需在 Accuracy Prompt 强化"语域/风格问题不归本维度"的边界声明
