# **大模型译文审校可靠性评测**

## 一、项目目标

回答一个问题：AI对翻译质量的自动判断，在什么维度、什么严重度上可以替代人工，什么维度、什么严重度上不能。

这个问题的答案，是审校Agent的重要设计依据。Agent产品设计逻辑不由维度单独决定，而取决于人机一致性水平是否足以覆盖该类错误的业务风险。同样的严重等级，发生在准确性维度上可能造成资金损失，发生在术语维度上可能只是轻微不适，两类维度对"AI可以独立判断"的信任门槛不同。评测是为了验证“大模型在不同语言类型中的可信程度不同”的假设并给出数据验证，进而基于评测证据进行产品化设计。指导的Agent设计逻辑并非按维度一刀切，而是看每类错误场景下的预期误判成本是否在业务可接受范围内。因此本文档每一项设计都服务于同一个核心产出：**四个维度各自的人机一致性估计（Cohen's Kappa）**

---

## 二、评测框架说明

### 2.1 为什么用MQM

MQM（Multidimensional Quality Metrics）是翻译与本地化行业广泛采用的分析式质量评估框架，是基于对二十余种已有评估指标的分析而建立，也被主流本地化行业沿用至今。选择MQM而非自建维度，是为了让评测结果具备行业可比性和方法论权威性。

MQM共有七个维度：Terminology、Accuracy、Linguistic Conventions、Style、Locale Conventions、Audience Appropriateness、Design and Markup，另有一个Custom兜底类别用于收纳无法归类的问题。

*MQM官网：[https://themqm.org/the-mqm-typology/](https://themqm.org/the-mqm-typology/)*

### 2.2 为什么只选四个维度

MQM本身强调"按项目需求裁剪"，不要求全部维度照单全收。结合出海本地化三类内容（营销文案/客服话术/UI文本）的实际风险点，本次评测选定：


| 维度                                   | 选用理由                                  |
| ------------------------------------ | ------------------------------------- |
| **Terminology** （术语一致性）              | 三类内容都强依赖术语/品牌词一致性，且判断标准最客观            |
| **Accuracy** （准确性）                   | 翻译质量的基础维度，任何内容类型都必须测                  |
| **Locale Conventions** （本地化规范）       | 数字/货币/日期格式规范，UI文本与客服话术强相关             |
| **Audience Appropriateness** （受众适配性） | 内容是否适配目标受众/是否存在文化冒犯风险，营销文案与客服话术的核心风险点 |


**未选用的维度及原因：**

- *Linguistic Conventions（语法拼写）*：现阶段AI翻译工具在此维度错误率极低，区分度不足，暂不纳入正式评测
- *Style（风格语气）*：语域一致性、句式节奏等方面与本次评测聚焦的文化风险维度关联较弱，且与Audience Appropriateness在称呼习惯、正式程度上有部分判断重叠,暂不纳入正式评测
- *Design and Markup（设计与标记）*：需要真实排版/UI渲染环境才能有效判断，本次语料为文本片段对比，不具备测量条件

**Custom类别的处理**：不参与统计意义上的一致性检验（无法定义操作性标准，无法计算Kappa），但保留作为人工复核环节的兜底选项，用于承接四个正式维度之外、评分者主观判断"有问题但归不了类"的情况。

### 2.3 严重度分级

采用MQM标准四级体系，每一级对应明确的用户影响程度，而非模糊的"好/坏"判断：


| 等级           | 定义                                |
| ------------ | --------------------------------- |
| **Neutral**  | 无错误，或错误极其轻微，完全不影响理解与使用            |
| **Minor**    | 存在瑕疵，但不影响理解，仅造成轻微不自然感             |
| **Major**    | 明显影响理解、专业度或用户体验，但不构成安全/法律/品牌层面的风险 |
| **Critical** | 导致误导性理解、功能性错误操作、品牌损害或法律合规风险       |




#### 等级边界判定规则：

四个等级的判定，按以下三个问题依次分流。上一问已确定等级的，不再进入后续问题；上一问未定级的，继续向下。

 **1.第一问：目标受众是否需要"停下来想"？**

- 读过去完全不需要停顿、不会感知到任何不对劲 → **Neutral**
- 能感知到不自然，但不需要停下来，理解不受影响 → **Minor**
- 需要停下来思考"这句话到底什么意思"才能继续 → 进入第二问

**2.第二问：**如果用户只看到这一条译文（无原文对照），会不会因此做出一个错误的、有实际代价的决定？

- 不会，最多体验受损或产生短暂困惑 → **Major**
- 会，用户可能因此错过时限、误操作、多付少收、触及法律或安全风险 →**Critical**
- **紧邻修正补充规则：** 如果该译文所在的**最小语义单元**（如同一 句群、同一段落、同一 UI 屏幕）内存在明确的修正信息，且同时满足以下三个条件：① 修正信息与错误信息**紧邻出现**（中间无其他干扰信息）；② 修正信息**足以完全消除**错误信息可能导致的误导；③ 读者**无需额外交互**（翻页、点击展开、查阅其他页面）即可看到修正信息；则严重度**上限为 Minor**，不判 Major。若三个条件中任一不满足（修正信息在下一页、需要点击才能看到、或修正本身含糊），则维持 Q2 的原始判定（Major 或 Critical）。评分者必须在 notes 中逐条核对①②③是否满足。

**3.第三问（仅针对Neutral/Minor边界模糊时启用）：如果整篇译文都被同类型、同程度的瑕疵浸染，目标受众的阅读体验是"流畅"还是"持续不适"？**

- 单个瑕疵可以忽略，但同类瑕疵密集出现时整体体验显著劣化 → **Minor**（不可以因为单条"就这一个地方"而放宽到Neutral）
- 单个瑕疵即使同类密集出现整体体验也不受影响 → **Neutral**
- **第三问操作化补充：**
  - **同类型：** 指同一维度、同一错误模式（如"所有 Don't X 都被增译为拒绝 X + 修饰词"）。
  - **密集出现的判定标准：** 假设该错误模式在全文中出现频率 ≥ 3 次/千字（或 UI 文本中 ≥ 2 处/屏），评估整体阅读体验。
  - 如果评分者无法确定是否"密集"，默认按 Minor 处理（保守原则）。

**边界风险旁路条款：**

三问流程以典型读者的阅读体验为判定基准。然而，某些译文对绝大多数读者完全无害，却在极端边界条件下可能导致用户遭受实际代价。

例如：原文"within 180 days of the payment date"（付款日起180天内，含当日）被译为"付款日期后的180天内"（字面理解为次日起算）。对99%的用户无影响，但如果某用户恰好在第180天操作退款，"后"与"起"的1天差异可能导致退款被拒。

当评分者识别出此类情况时，适用以下规则：

- Severity等级不因边界风险而改变。三问怎么判就怎么判。上述案例中，典型读者阅读"付款日期后的180天内"完全不需要停下来想，Q1直接定级Neutral。
- 必须在 notes 中标记 `[边界风险]`，写明三项内容：触发条件（什么情况下会出问题）、影响范围（多少用户可能受影响）、潜在后果（用户会遭受什么损失）。
- 该标记进入全量阶段的 Failure Analysis，与语料的Risk Level交叉。若该语料的Risk Level为High（如涉及资金操作的退款政策、支付流程），则自动进入人工复核队列。

设计原理：边界风险不需要通过膨胀Severity等级来表达。Severity管"译文实际错了多少"，Risk Level管"如果错了后果多严重"。边界风险是两者的交叉地带，用标记触发交叉复核，比硬塞进Severity等级更干净，也避免了"理论上可能有人受害"的假想无限拉高所有译文的严重度。

#### 使用说明：

第一条规则覆盖所有等级的最初分流。第二条是Major与Critical的强制分界线，它的判定不依赖评分者的语言直觉，而是要求评分者想象一个具体场景：用户只看到这句译文，没有原文对照，没有其他渠道确认信息，然后判断用户会不会做出对自己有害的行为。第三条是兜底规则，防止评分者在同一维度上对Neutral/Minor的敲定逐条漂移。  
各维度的具体锚点例句见第三节。评分时先走上述三问流程，再参照对应维度的锚点确定等级。

#### 严重度（Severity） 与风险等级（ Risk Level） 的关系（防止混淆）

**Severity（本节）和 Risk Level（§4.3）是两个正交维度，评分时不应混淆。**

- **Risk Level**：源文的属性，译前标注。问的是"这段原文一旦翻错，后果有多严重"。标注时不看译文。
- **Severity**：译文错误的属性，译后评分。问的是"这条译文实际错得多严重"。评分时不查 Risk Level。

同一段 High Risk 原文：翻译完美 → Severity = Neutral（高风险被化解了）；翻译把金额搞反 → Severity = Critical（高风险被触发了）。同一段 Low Risk 原文：翻译再差，Severity 天花板也是 Major——"请稍候…"翻得再离谱也造不成资金损失。

两者在全量阶段构成 **Confidence（人机一致性）× Risk（语料风险）** 的二维决策矩阵，作为 Agent 分流规则的输入（见 §4.3）。

## 三、四个维度的操作性定义与评分锚点



### 3.1 Terminology（术语一致性）

**操作性定义**：译文中的专有名词、品牌词、功能名、行业术语，是否（1）在同一批语料内前后译法一致；（2）符合该内容类型已有的惯例译法；（3）语义边界未被错误缩小或扩大。只判断术语本身对错，不涉及句子是否通顺。


| 内容类型 | 判断对象                  | 判断依据                 |
| ---- | --------------------- | -------------------- |
| 营销文案 | 品牌名、产品系列名、slogan核心概念词 | 品牌官方译名/已公开本地化物料      |
| 客服话术 | 功能名、操作步骤名词            | 产品帮助文档/FAQ既有译法       |
| UI文本 | 按钮名、菜单项、状态提示词         | 同类产品UI惯例、产品内其他界面既有译法 |


**严重度锚点**：

- **Neutral**：术语译法准确且与语料集内其他位置一致
- **Minor**：译法不算错，但非领域惯用译法，造成轻微陌生感，不影响理解
- **Major**：同一术语在语料集内出现两种译法，造成读者对"是否同一功能"产生困惑
- **Critical**：术语误译导致功能性误导，或品牌名错误译法造成识别混乱/法律风险

**示意例句**：

- Major：产品中"Workspace"在设置页译为"工作区"、在导航栏译为"工作空间"，用户会疑惑这是不是两个不同功能，但点进去发现是同一功能，未造成误操作
- Critical："Permanently Delete"被误译为语义相近但实际后果不同的措辞（如暗示"可恢复"的说法），用户据此点击后数据被不可逆删除，造成功能性误操作

**判断单元规则**：

一致性以**单条译文**（单个 tool_anon × 单个 corpus_id）为判断单元。跨译文（A/B/C 之间）的同义变体（如"工作区/工作空间"分属不同工具译文）不构成任一单条的一致性扣分项，但应在 Pilot/全量汇总报告中登记为"跨译文变体"，作为三款工具术语处理风格横向对比的观察项，不参与单条评分。注意：本规则只管"同一批语料内前后译法一致"这一条怎么判（操作性定义第 1 条）；译法是否准确（第 2 条符合惯例译法、第 3 条语义边界）不受影响，仍按原标准判定。

**术语撞车规则**：

当译法与同一产品官方物料中**另一术语的既定译法相同**（撞车）时：

1. 一般撞车 → **保底 Minor**（即使译文单独看可理解）；
2. 若撞车对象与源术语处于同一操作流程的不同阶段（如 PayPal：dispute→claim→appeal 三阶段），存在流程阶段误判风险 → **保底 Major**，再按第二问判断是否升 Critical。

判定前提：撞车事实必须附官方出处（遵循"术语断言必须外部核实"纪律），无出处的"撞车"断言不成立。

**notes 记录义务**：

定级为 Minor 及以上的评分，notes 必须显式记录三问判定路径（`Q1：是/否+一句理由` `Q2：是/否+一句理由`；Q3 仅在 Neutral/Minor 边界启用时标注）。凡断言"官方既有译法/行业惯例"必附出处。此规则适用于全部四个维度。

### 3.2 Accuracy（准确性）

**操作性定义**：译文是否准确对应原文的命题内容（propositional content），是否存在扭曲、遗漏、增添原文信息的情况。这是MQM定义中最核心的维度，即判断"意思有没有传达对"，与术语、风格无关。


| 内容类型 | 判断对象                | 典型风险            |
| ---- | ------------------- | --------------- |
| 营销文案 | 卖点、优惠条件、行动号召的具体内容   | 优惠力度/适用条件被夸大或遗漏 |
| 客服话术 | 操作步骤、政策条款（退款规则、时限等） | 步骤顺序错乱、关键条件遗漏   |
| UI文本 | 功能说明、状态提示的具体含义      | 提示信息与实际功能状态不符   |


**严重度锚点**：

- **Neutral**：译文完整、准确传达原文全部命题内容
- **Minor**：存在细微增译/漏译，但不改变核心信息，读者仍能获得正确理解
- **Major**：遗漏或增加了会影响用户决策的信息（如条件、限制），但未造成安全或资金损失
- **Critical**：译文与原文含义相反，或遗漏关键信息导致用户可能遭受资金损失、误操作或法律风险

**Accuracy 维度的增译判定规则：**

- 增译**命题信息**（如添加原文不存在的条件、限制、数据）→ 按严重程度判定。
- 增译**修辞/语气成分**（如添加修饰词、感叹号、营销话术）→ 不改变命题，**Accuracy** 维度判 **Neutral**，但应在 **Style** 或 **Audience** 维度评估语气偏移。
- Notes 中应明确标注增译的类型（命题性增译 vs 修辞性增译），以便后续聚合分析。

**示意例句**（构造语料，非真实品牌）：

- Major：原文"部分退款将在3-5个工作日内到账"，译文漏译"部分"二字，但退款页面后续步骤会显示具体到账金额，用户不会因此实际损失金钱，只是短暂产生错误预期
- Critical：原文"超过30天未联系客服，订单将自动关闭且无法退款"，译文因漏译导致条件消失或语义相反，用户不知情错过退款窗口，造成实际资金损失

**Major与Critical的判断标准**："如果这条译文是用户获取信息的唯一来源，用户会不会因此做出一个错误的、有实际代价的决定？“ 如果答案为"会"，判Critical（错过时限、多付/少收款、误操作、触及安全或法律风险）；答案为"不会，顶多体验受损或产生短暂困惑"，判Major。区分点不是错误是否明显，而是错误是否导致不可逆或有实际代价的后果。

**Accuracy 与 Terminology 的边界判定（替换测试）：**

**对译文中的每一个术语，问一个问题：如果用户只凭这个术语去执行操作或紧邻修正补充规则做出判断，会不会走错路？**

- **不会走错路（名称不标准但不影响理解和操作）→ 归 Terminology，Accuracy 不扣分。**
- **会走错路（术语引导了错误的想法，导致对流程/条件/权利的理解偏移）→ Accuracy 评估命题扭曲程度，Terminology 同步记录。两个维度独立评分。**

### 3.3 Locale Conventions（本地化规范）

**操作性定义**：译文是否符合目标地区对数据类元素的格式惯例，包括数字格式、货币格式、日期时间格式、度量单位等。明确不涉及"内容本身是否适合该地区"（这属于Audience Appropriateness维度），本维度只判断**格式层面**的合规性。


| 内容类型 | 判断对象                              |
| ---- | --------------------------------- |
| 营销文案 | 价格显示、促销日期格式                       |
| 客服话术 | 时限描述（如"3个工作日"是否符合当地工作日历惯例）、货币金额格式 |
| UI文本 | 日期选择器格式、数字千分位符号、货币符号位置            |


**严重度锚点**：

- **Neutral**：所有格式元素均符合目标地区惯例
- **Minor**：格式存在瑕疵但含义仍可正确理解（如千分位符号习惯性误用，数字本身无歧义）
- **Major**：格式错误可能造成理解偏差（如日期格式月/日顺序混淆，导致时间理解错误）
- **Critical**：格式错误直接导致金额/时限被误解，可能造成用户实际损失或合规问题

**示意例句**（构造语料，非真实品牌）：

- Minor：原文："Your order will arrive by 2026-07-15."译文："您的订单将于2026-07-15送达。"——ISO日期格式（年-月-日，用连字符分隔）没有转换成中文书面惯用的"2026年7月15日"格式，行文不够符合中文正式文本的书写惯例，读起来略显生硬。但因为ISO格式本身就是"年-月-日"的顺序，恰好和中文日期惯例的顺序一致，读者不会把这个日期误读成别的日期，只是格式没有本地化，不构成理解障碍
- Major：原文(英文,使用美式月/日/年格式)："Your subscription renews on 03/04/2026. See details in your March renewal email."（注:原句同时用文字提及了"March"，为月份提供了文字层面的辅助确认）译文："您的订阅将于03/04/2026续费，详情请查收3月续费邮件。"其中数字日期没有转换成中文惯用的"2026年3月4日"格式，但因为后半句提到"3月"，中文读者仍能从文字确认这是3月，不会被数字部分误导，未产生误解
- Critical：译文："您的订阅将于2026年4月3日续费。"译者未识别原文遵循美式"月/日/年"顺序，把03当成日、04当成月，日期理解完全颠倒。用户实际续费日在3月4日，却被告知是4月3日，可能因此错过取消订阅的窗口，产生非预期扣款。纯数字日期"03/04/2026"直接照搬无转换，且无文字月份辅助判断，中文读者大概率理解成"3月4日"而非实际的"4月3日"，导致预约/截止日期被完全理解错误

---



### 3.4 Audience Appropriateness（受众适配性）

**操作性定义**：译文内容本身（而非格式）是否适合目标受众/目标地区，是否存在因文化差异导致的无效表达、冒犯性内容或理解障碍。这是四个维度中主观性最强、也最贴近"文化风险"的一项，对应Agent项目里"文化风险识别"这一步的评测依据。


| 内容类型 | 判断对象                               |
| ---- | ---------------------------------- |
| 营销文案 | 文化隐喻、幽默、颜色/数字象征意义是否在目标文化中同样适用或产生歧义 |
| 客服话术 | 语气的正式程度、称呼习惯是否符合当地沟通规范             |
| UI文本 | 图标/表达是否存在目标地区的文化敏感性问题              |


**严重度锚点**：

- **Neutral**：内容在目标文化语境下自然、恰当，无理解或接受障碍
- **Minor**：表达略显生硬或"翻译腔"，目标受众能理解但会感到不自然
- **Major**：内容在目标文化中含义空洞或产生偏差理解（如直译的隐喻在目标语言中不成立），显著削弱营销/沟通效果
- **Critical**：内容在目标文化中构成冒犯、禁忌触碰，或造成严重负面观感，存在品牌声誉风险

**示意例句**（构造语料，非真实品牌）：

- Minor：原文："We've got your back — cancel anytime, no questions asked."译文："我们支持您，随时可以取消，不问理由。"直译"got your back"为"支持您"，行文比中文原生表达略显生硬、带点翻译腔，但读者能准确接收到"这是一个宽松、不为难用户的取消政策"这个意思，效果基本传达到位 
- Major：原文（含习语比喻）："Don't let your data go up in smoke."（英文习语，字面"化为烟雾"，比喻"数据凭空消失、损失惨重"）译文："别让您的数据变成烟雾。"字面直译，中文读者无法从"变成烟雾"联想到"数据丢失"这个比喻含义，读到这句话会困惑这到底想说什么，原文想营造的"数据安全紧迫感"没有传达到位，读者大概率直接跳过这句话
- Critical：文案中的手势/颜色/数字象征直译后在中文语境中带有负面或忌讳含义，读者产生冒犯感，对品牌产生负面观感。如原文（英文促销文案）："Get 4 amazing features for the price of 1 — grab this deal before it's gone!"译文：标题翻译为强调数字"4"并放大呈现（如"限时4折抢购，第4件立减，仅剩4小时"），中文营销语境里"4"因谐音"死"，电商定价、楼层编号、促销文案通常会刻意规避将其作为卖点数字使用。译文没有识别这个文化忌讳，把原文里中性的"4"直接保留放大，在部分中文受众（尤其传统观念较重的用户群体）中可能引发不吉利联想，损害品牌观感

## 四、语料抽样方法



### 4.1 分层依据

本次评测按内容类型分层抽样，而非从单一语料池随机抽取。原因：营销文案、客服话术、UI文本在术语密度、文化依赖程度、格式规范要求上存在系统性差异。如果AI审校能力在这三类上表现不同，Agent的规则就需要按内容类型区分，而非一套规则通用。三类内容是否确实存在人机一致性的差异，是本次评测要回答的问题之一，分层抽样是让这个比较得以进行的前提。


|        | 营销文案          | 客服话术         | UI文本          |
| ------ | ------------- | ------------ | ------------- |
| 术语密度   | 中（品牌词、slogan） | 中高（功能名、政策术语） | 高（按钮、菜单、状态词）  |
| 文化敏感度  | 高（隐喻、幽默）      | 中（称呼习惯、语气）   | 低（多为功能性表达）    |
| 格式规范要求 | 中（价格、日期）      | 高（退款规定、时限）   | 高（日期选择器、货币符号） |




### 4.2 内容类型

**营销文案** 

- 选取标准：未进入中国市场的海外品牌原生英文文案，尚无官方中文版本
- 来源类型：SaaS/DTC官网、Product Hunt产品描述、社媒广告文案（Instagram/LinkedIn）
- 来源配比：Product Hunt来源不超过总量的60%，避免样本风格过度集中在B2B调性

**客服话术**

- 选取标准：英文原生客服标准英文原生客服帮助中心（Help
Center）的消费者向政策说明与操作指引文本，内容涉及资金、时限、条件类风险
- 意图类目：选取与退款、支付、争议、取消、计费、配送相关的六类消费者高频接触的客服回复场
景，优先截取同时含金额数字与时限窗口的段落，此类文本在 Accuracy 与 Locale
Convention 维度上具有天然的高区分度

**UI文本**

- 选取标准：消费级、社交/生活类开源项目的英文locale文件，按功能模块分层抽取，覆
盖按钮标签、操作指令、错误提示、确认弹窗、状态通知、导航标签与权限请求七类 UI
语义类型，确保短文本（单按钮词）、中等文本（操作指令/状态通知）与长文本（权限说
 明/弹窗条件句）三类长度均有分布。
- 排除：纯开发者工具类仓库（此类文本偏技术化，与出海消费级场景脱节）
- 约束：已有的人工译文不进入AI评测，仅作为评分者校准参照

**抽样规则**

1. 试跑：每类10条，统计严重度分布。若每类10条试跑中Major/Critical出现少于2条，正式抽样时有意识纳入更高风险特征文本。
2. 正式量：以每严重度等级至少5-8个观测点为下限反推总量，预计每类30-50条、合计90-150条
3. 抽样方法：固定间隔抽样，起始位置随机确定
4. 每条样本可独立判断，不依赖额外上下文



### 4.3 语料风险等级标注（Risk Level Annotation）

严重度（§2.3）评的是"译文错得多严重"，风险等级体现的的是“一旦翻错所造成的后果"。前者是评分时的判断，后者是语料入库时的元数据。两者在后续 Reliability Matrix 中构成 Confidence × Risk 二维决策模型的 Risk 轴（？待考虑）。

标注时间：翻译生成前，只看原文。
标注原则：关注“翻错对用户造成的影响及后果”。

**通用判断标准**

找出本条文本的核心信息承载元素（用户据此做决定的词/短语，而非每个词），设想该元素被大模型漏译/曲解/反转的最坏合理情况，判断后果等级。


| 等级         | 通用定义                                    |
| ---------- | --------------------------------------- |
| **High**   | 翻译错误导致用户资金损失、错过法定时限、人身/家庭安全风险，或公司触碰合规红线 |
| **Medium** | 翻译错误导致用户决策偏差、操作反复、品牌体验下降，但不产生不可逆的实际损失   |
| **Low**    | 翻译错误不影响用户理解、决策或操作，或用户可自行纠正              |


---

**营销文案**

用户行为：浏览→购买决策。风险载体：定价、功能承诺、健康/环保声称、竞争对比。形容词和品牌调性差异不算风险。


| 等级         | 一句话标准                         |
| ---------- | ----------------------------- |
| **High**   | 含具体金额、可验证的竞争声称、或涉及隐私/合规的功能描述  |
| **Medium** | 含功能承诺或品牌定位，但用户不会仅凭这一句做付费决定    |
| **Low**    | 纯品牌介绍、形容词堆砌、故事叙述——翻错了也不影响购买判断 |


**客服话术**

用户行为：阅读→操作（退款/取消/申诉）。风险载体：数字、时限、金额、条件逻辑、否定词。


| 等级         | 一句话标准                                 |
| ---------- | ------------------------------------- |
| **High**   | 含数字/金额/时限/条件/否定词中任一项→翻错用户可能亏钱或错过维权窗口 |
| **Medium** | 含操作路径或功能术语→翻错用户找不到入口，但不产生不可逆损失       |
| **Low**    | 纯信息解释或确认通知，不含数字也无条件→翻错不影响用户任何行为      |


**UI 文本**

用户行为：识别→点击/输入。风险载体：动作词、安全术语、权限后果。判断依据：操作后果的可逆性。确认弹窗不降级——用户无法确认一个自己看不懂的标签。


| 等级         | 一句话标准                               |
| ---------- | ----------------------------------- |
| **High**   | 操作不可逆。如安防设防/撤防、踢人、支付账户恢复码丢失、权限永久变更等 |
| **Medium** | 操作可逆但有额外成本。如重填输入、重找功能、恢复设置等         |
| **Low**    | 无操作后果—。如导航标签、状态提示、进度指示、错误信息等        |


**三类对照**


|           | 营销文案       | 客服话术        | UI 文本    |
| --------- | ---------- | ----------- | -------- |
| 用户行为      | 浏览→决策      | 阅读→操作       | 识别→点击    |
| High 信号   | 定价/合规/竞争声称 | 数字+时限+金额+条件 | 不可逆操作    |
| Medium 信号 | 功能承诺/品牌定位  | 术语/操作路径     | 可逆但有成本   |
| Low 信号    | 形容词/故事     | 纯解释/确认通知    | 导航/状态/提示 |

## 五、评分流程



### 5.1 翻译生成

**翻译工具**：GPT-4o / Claude / Gemini **只生成译文**

**翻译Prompt**（三款工具使用完全相同的prompt）：

> Translate the following English text into Simplified Chinese. Output only the translation. No explanations, no notes, no alternatives.

**设计理由**：不加目标受众上下文（如"for a Chinese consumer audience"），目的是让翻译质量产生足够方差，从而对评分框架形成充分的压力测试。带上下文的翻译会缩小工具间差异，反而不利于验证框架的区分能力。

**匿名化**：每条语料的三份译文随机编号为A/B/C——同一字母在不同语料行可能对应不同工具（非全局固定）。例如PILOT-001的A可能是GPT，PILOT-002的A可能是Claude。对照表存入 `pilot/pilot_tool_map.csv`，评分者在完成全部评分前禁止查看对照表。此步骤是为了避免评分者因工具口碑（如"GPT-4o翻的肯定更好"）产生确认偏差。

此步骤只生成译文，不涉及评分动作；GPT-4o / Claude / Gemini 在此步骤的角色是"译员"，与 §5.4 中 Qwen 作为"评分员"的角色分离。

### 5.2 译文匿名化处理

翻译生成完成后，将同一条语料对应的三份译文随机编号为A/B/C，编号与工具的对应关系单独保存，评分者在完成全部评分前不得查看对照表。此步骤是为了避免评分者因工具口碑（如"这是GPT-4o翻的"）产生确认偏差，是人工评分前必须完成的前置动作。

### 5.3 人工评分

评分者本人（专业背景：翻译学）对匿名化后的全部译文，在四个维度上独立打分。评分完成、提交后再解密工具对照表，确保打分过程不受工具身份影响。

### 5.4 AI自动评分

评分工具：Qwen **独立评分**

**Qwen** 承担AI评分员角色：使用依据本文档3.1-3.4节维度定义与锚点撰写的Prompt，对§5.2中已匿名编号的译文进行自动评分。

此步骤与5.1的翻译生成是两个独立动作：5.1中GPT-4o/Claude/Gemini的角色是"译员"（产出译文），5.4中 Qwen 的角色是"评分员"（对译文打分），执行时需在数据记录中明确区分这两种角色产出的数据，避免混淆。

### 5.5 评分原则

每个维度独立判断，避免因译文整体印象好坏产生晕轮效应（halo effect），即使整体流畅，某一维度确有问题仍需如实评级。

## 六、实际执行说明（与原方案的历史差异）

评测方案早期版本曾考虑由 GPT-4o / Claude / Gemini 三款生成模型兼任 AI 评分员（自评与互评并行）。正式执行改为生成与评分角色分离：

- GPT-4o / Claude / Gemini：只生成候选译文（见 §5.1）；
- Qwen：正式独立 AI 评分员（见 §5.4）；
- 人工：按同一套四维评分标准独立评分。

后续全部统计（一致率 / Cohen's Kappa / Gwet's AC1 / 12 格矩阵）均以实际执行口径为准。本文档不描述未实际执行的双评分员交叉验证流程。
