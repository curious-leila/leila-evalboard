# 可靠性矩阵（Reliability Matrix）

> 数据：改判后人工参考标注 vs Qwen AI 评分（180 条判断，Pilot 数据冻结：2026-08）
>
> 公开数据：[`data/evaluation-results.csv`](../data/evaluation-results.csv)
>
> 用途：维度一致率 × 内容风险等级 → Pilot 候选人工介入策略

---

## 方法说明

### 风险等级（Case Risk） vs. 评测第二问（q2）

- **风险等级（Case Risk）**：在评价具体译文质量之前，基于原文内容及业务场景预先标注的案例级风险，表示“该内容一旦发生误译，潜在用户/业务后果有多严重”。
- **q2**：四维评分 Prompt 内部的第二问，表示“当前已识别出的具体翻译问题是否产生实际代价”。

两者为独立变量：

- q2 不生成、不修改 Case Risk；
- 可靠性矩阵（Reliability Matrix） 的风险轴只使用预先标注的 Case Risk。

本次仅补充定义，不修改任何已有评测结果。

## 二、关键发现



### 发现 1：唯一红灯 = Terminology × High Risk（61%）

- 12 条人机分歧中，**7 条集中在 Terminology × High Risk 格子**（PayPal 争议流程 claim→申诉/索赔、Kick→踢/踢出）
- 且这 7 条全部是 **AI判定有误**，AI在notes中编造"官方译法"（claim=申诉/索赔）后判 Neutral，人工查证为错
- **错因模式明确**：AI 在高风险（金融/资金/不可逆操作）语料的术语判断上，倾向"编造依据 + 放行"



### 发现 2：Terminology 的"弱"是局部的，不是全面的

- 维度级 Kappa 只有 0.464（看起来"中等偏弱"）
- 但矩阵拆开后：**术语 × 中风险与术语 × 低风险的样本人机一致率为 100%**（18/18 与 9/9）
- 结论：不是"术语维度不可信"，而是"术语 × 高风险"在本次 Pilot 样本中不可信；决策规则应落到格子级



### 发现 3：其余 11 个格子全部 🟢（≥94%）

- Accuracy / Locale Conventions / Audience Appropriateness 各组合在本次 Pilot 中人机一致率均 ≥94%
- 唯一例外：Locale × Medium 94%（S031 中英混排空格，框架歧义项，不计入 AI 能力问题）

## 四、量化结果（人工复核量估算）

以 180 条评分任务为基准（45 语料 × 4 维度）：


| 场景           | 人工复核量                                                                     | 说明               |
| ------------ | ------------------------------------------------------------------------- | ---------------- |
| 无 AI 分流（全人工） | 180 条（100%）                                                               | 传统 MTPE 基线       |
| 有 AI 分流（本矩阵） | 18（Term×High）+ 18×10%（Acc×High）+ 18×10%（Loc×Med）+ 其余×5% ≈ **28 条（15.5%）** | 人工复核量降 **84.5%** |


> 注：此处为基于 Pilot 实测一致率的分流规则推演，非预测承诺。数字可直接审计（格子 → 条数 → 比例）。

## 五、对后续审校 Agent 设计的三条输入（Pilot 边界内）

1. **强制人工兜底**：Terminology 维度 + Risk Level High 的内容（退款政策、支付流程、不可逆操作）**永远不走 AI 自动放行**，即使 AI 自信
2. **AI 严格模式**：高风险语料启用"术语断言必须附出处"检查（S061/S065/S069 教训：AI 编造官方译法）——无出处的术语断言标记人工复核
3. **人机互查**：中低风险语料 AI 自动评分，但保留 5% 抽检——因为 Pilot 证明人工也会漏检（S077/S081/S084"发送退款"案例），抽检是双向兜底

## 六、事实边界

> 本矩阵来源于当前 Pilot 样本（15 条语料、180 次判断），只用于形成候选人工介入策略；不得将样本内一致率直接外推为生产环境真实准确率。

## 七、与后续审校 Agent 的关系

Project 2（本项目）的产出是评测证据与 Pilot 候选策略：

- 评测证据：模型在不同"质量维度 × 内容风险"组合下的人机一致性；
- 候选策略：Pilot 数据驱动的人工介入比例（100% / 10% / 5%）。

Project 3（审校 Agent）在 Project 2 证据基础上，进一步将策略抽象为自动信任（AUTO_TRUST）/ 抽样复核（SAMPLE_AUDIT）/ 人工验证（HUMAN_VERIFY）等自动化权限，并结合运行时质量判断、证据状态与失败条件生成最终处理路径。

两者是策略演进关系，不是完全相同的静态规则表；Project 2 的 Pilot Policy 不因 Project 3 的产品化改动而反向改写。
